# YubiKey Attestation — Developer Guide

## Overview

YubiKey attestation proves that a workload private key was generated on a
genuine Yubico hardware security key and has never left the device.  Unlike TPM
attestation (which uses OS-level APIs), YubiKey attestation uses the **PIV
(Personal Identity Verification)** smart card interface via the `yubikit` and
`yubikey-manager` Python libraries.

## The Attestation Flow (5 Checks)

Entry point: `attest_yubikey(config: WorkloadConfig)`.

### Check 1: YubiKey Detection

```python
from ykman.device import list_all_devices

devices = list_all_devices()
```

- **No devices** → early return with failure
- **Multiple devices** and no `config.yubikey_serial` → error listing all serials
- Extracts serial, firmware version (major.minor.patch), and form factor

### Check 2: Firmware Version Gate

| Firmware | Support Level |
|---|---|
| < 4.3.0 | ❌ Attestation not supported |
| 4.3.0 – 4.x.x | ⚠️ Attestation works but serial NOT in attestation cert |
| ≥ 5.0.0 | ✅ Full attestation support |
| ≥ 5.7.4 | ✅ New multi-level certificate chain |

### Check 3: Key Attestation Certificate (Core)

```python
from yubikit.piv import PivSession

with device.open_connection(SmartCardConnection) as conn:
    piv = PivSession(conn)
    attest_cert = piv.attest_key(slot)  # ← THE CORE OPERATION
```

**`piv.attest_key(slot)`** asks the YubiKey to generate a certificate proving:
- The key in the given PIV slot was **generated on-device** (not imported)
- The key has **never left the hardware**
- The certificate is signed by the device's unique F9 attestation key

> **Critical:** If `attest_key()` throws an exception, the key was IMPORTED
> (not generated on the YubiKey).  This is the primary distinction — imported
> keys cannot have hardware residency proven.

Produces artifact: `key_attestation.pem`

### Check 4: Attestation Chain Verification

```python
f9_cert = piv.get_certificate(SLOT.ATTESTATION)  # Factory-provisioned cert
_verify_yubico_chain(attest_cert, f9_cert)
```

The chain is verified from leaf to root:

**Legacy chain (firmware < 5.7.4):**
```
Yubico PIV Root CA
  └─ F9 Device Attestation Cert (unique per YubiKey, factory-flashed)
       └─ Key Attestation Cert (generated by attest_key)
```

**New chain (firmware ≥ 5.7.4):**
```
Yubico PIV Root CA 2
  └─ Yubico Attestation Intermediate B1
       └─ Yubico PIV Attestation B1
            └─ F9 Device Attestation Cert
                 └─ Key Attestation Cert
```

**Bundled Root CAs** (in `roots/yubico/`):

| File | Purpose |
|---|---|
| `yubico_piv_root_ca.pem` | Legacy root (pre-5.7.4) |
| `yubico_piv_root_ca_2.pem` | New root (5.7.4+) |
| `yubico_attestation_intermediate_b_1.pem` | Intermediate for new chain |
| `yubico_piv_attestation_b_1.pem` | PIV attestation intermediate |

### Check 5: Attested Device Properties

Parses Yubico-proprietary OID extensions from the attestation certificate:

| OID (`1.3.6.1.4.1.41482.3.x`) | Property | Encoding |
|---|---|---|
| `.3` | Firmware version | 3 raw bytes: major, minor, patch |
| `.7` | Serial number | DER-encoded INTEGER (tag `0x02`) |
| `.9` | Form factor | 1 byte → USB-A/C Keychain/Nano/Lightning/Bio |
| `.8` | PIN + Touch policy | 2 bytes: PIN policy, Touch policy |

**PIN Policies:** Never (1), Once (2), Always (3)
**Touch Policies:** Never (1), Always (2), Cached (3)


## PIV Slots

| Slot | Enum | Typical Use |
|---|---|---|
| `9a` | `SLOT.AUTHENTICATION` | **Default** — workload key |
| `9c` | `SLOT.SIGNATURE` | Digital signature |
| `9d` | `SLOT.KEY_MANAGEMENT` | Key management/encryption |
| `9e` | `SLOT.CARD_AUTH` | Card authentication |
| `f9` | `SLOT.ATTESTATION` | **Read-only** — factory-provisioned attestation key |


## Key Generation (Keystore Module)

**File:** `wif_bunker/keystore/yubikey.py`

### Supported Algorithms

| Config Name | YubiKey KEY_TYPE | Min Firmware |
|---|---|---|
| `es256` | `ECCP256` | 4.3.0 |
| `es384` | `ECCP384` | 4.3.0 |
| `rsa2048` | `RSA2048` | 4.3.0 |
| `rsa4096` | `RSA4096` | **5.7.0** |

### Security Initialization

On first use, if the management key is the factory default:
1. Generate random PIN (8 chars), PUK (8 chars), management key (24 bytes/TDES)
2. Change all credentials on the YubiKey
3. Save to `~/.config/wif-bunker/yubikey_{serial}.json` with `chmod 0o600`

On subsequent uses, load from the stored config file.

### Key Creation Flow

```python
piv.authenticate(mgm_key)  # Management key auth
piv.verify_pin(pin)  # PIN verification
pub_key = piv.generate_key(  # Generate on-device (never exportable)
    slot, key_type, pin_policy=PIN_POLICY.ONCE, touch_policy=touch_policy
)
piv.put_certificate(slot, cert)  # Import signed cert
```


## PKCS#11 for mTLS

For mTLS via ECP (External Credential Provider), the module finds the
PKCS#11 library for the YubiKey:

**Search paths:**
- `YKCS11_MODULE` environment variable
- Platform-specific defaults:
  - Linux: `/usr/lib/x86_64-linux-gnu/libykcs11.so`, etc.
  - macOS: `/usr/local/lib/libykcs11.dylib`, Homebrew paths
  - Windows: `C:\Program Files\Yubico\*\libykcs11.dll`

Also auto-discovers the PKCS#11 slot ID via `pkcs11-tool --list-slots`.


## Error Handling

### Import vs Generate Detection

**The most critical error case.**  If `piv.attest_key(slot)` throws an
exception, the key was imported rather than generated on-device.  The
attestation report clearly communicates this:

> "Key in slot 9a was imported (not generated on the YubiKey).
>  Hardware key residency cannot be proven for imported keys."

### Multiple YubiKeys

Both attestation and keystore modules handle this identically:
- If >1 YubiKey connected and no `--yubikey-serial` → fail with actionable
  error listing all detected serial numbers

### Missing Dependencies

`yubikey-manager` and `yubikit` are lazily imported.  If not installed:
```
supported=False
detail="Install with: pip install wif-bunker[yubikey]"
```

### Chain Verification Robustness

`_verify_yubico_chain()` handles:
- Both RSA (`PKCS1v15`) and EC (`ECDSA`) signature verification
- Issuer matching via raw `public_bytes()` comparison (not string matching)
- Max chain depth of 5 to prevent infinite loops
- Missing root CA PEM files → explicit failure with detail message

### PyInstaller Support

Both `_verify_yubico_chain` and `verify_ek_chain` detect `sys.frozen` /
`sys._MEIPASS` to locate bundled root certs inside PyInstaller packages.

### DER Encoding Edge Case

Serial number parsing in `_parse_attested_properties` handles both:
- DER-encoded INTEGER format (tag `0x02`, length, value)
- Raw byte format as fallback


## Key Differences from TPM Attestation

| Aspect | YubiKey | TPM |
|---|---|---|
| Attestation method | `piv.attest_key()` → cert chain | PCP properties (Windows) / `tpm2_certify` (Linux) |
| What's proven | Key generated on-device, never exported | Key bound to specific TPM |
| Trust root | Yubico Root CA (bundled) | TPM manufacturer EK cert |
| Device identity | Serial number in attestation cert | EK certificate |
| Admin required | No | Maybe (tss group on Linux, admin on Windows for some ops) |
| Multi-device | Serial number selection | N/A (one TPM per machine) |
| Key import risk | Yes — imported keys can't be attested | No — TPM keys are always non-exportable |


## Attestation Checks Summary

| # | Check | Method | What It Proves |
|---|---|---|---|
| 1 | YubiKey Detection | `ykman.device.list_all_devices()` | Device is connected |
| 2 | Firmware Version | Version comparison | Attestation API available |
| 3 | Key Attestation | `piv.attest_key(slot)` | Key was generated on-device |
| 4 | Chain Verification | `_verify_yubico_chain()` | Device is genuine Yubico hardware |
| 5 | Properties | OID extension parsing | Firmware, serial, policies confirmed |
