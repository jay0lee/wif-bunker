# Linux TPM Attestation — Developer Reference

This document serves as a reference for HOW to perform TPM attestation on Linux. It explains the concepts, APIs, and gotchas for verifying cryptographic keys using a physical TPM 2.0.

## 1. Overview

TPM attestation proves two fundamental properties:
1. **Key Residency**: A specific cryptographic key was generated by and resides securely inside a physical TPM hardware module.
2. **TPM Genuineness**: The TPM module itself is a genuine hardware device produced by a recognized manufacturer, rather than a software emulator or compromised device.

**The Trust Chain:**
Attestation relies on a hardware root of trust. The chain flows as follows:
`TPM Hardware` → `EK (Endorsement Key)` → `EK Certificate` → `Manufacturer Intermediates` → `Manufacturer Root CA`

## 2. Architecture

The Linux TPM stack provides a path from user space down to the hardware.

- **TPM 2.0 Hardware**: The physical chip (e.g., Intel, AMD, Nuvoton, Infineon).
- **TPM2 Resource Manager**: The kernel abstraction (`/dev/tpmrm0`) that handles concurrent access and session swapping.
- **TSS2 API**: The standard C library suite (`libtss2-dev`) wrapping the TPM commands.

### Two API Options for Developers

1. **tpm2-tools CLI**: Shell commands like `tpm2_createek`, `tpm2_certify`. Good for bash scripts but hard to use securely via `subprocess` due to temporary files, hex-encoding quirks, and parsing unstructured output.
2. **tpm2-pytss Python Library**: Python bindings for the TSS2 API. Provides programmatic access to the TPM via standard C structures.

**Recommendation:** Use `tpm2-pytss` for all cryptographic and stateful interactions (creating keys, policy sessions, credential activation, certifying). Use the CLI `tpm2_getekcertificate` ONLY for fetching the manufacturer certificate, as it handles HTTP downloads that the core TSS library does not.

## 3. The Attestation Flow (6 Steps)

Here is the 6-step flow comparing the traditional CLI tools with the recommended `tpm2-pytss` approach.

### Step 0: Prerequisites

- Install `libtss2-dev` package on the system.
- Install `tpm2-pytss` and `python-pkcs11` via pip.

### Step 1: Extract EK Certificate

Extract the certificate provisioned by the manufacturer that vouches for the Endorsement Key.

**CLI (`tpm2-tools`):**
- NVRAM Read: `tpm2_nvread -C o 0x01C00002 -o ek_cert.der`
- Manufacturer Fetch: `tpm2_getekcertificate -u ek_pub.tpm2 -o ek_cert.pem`

**Library (`tpm2-pytss`):**
- NVRAM Read: Use `ESAPI.nv_read()` on the NV index.
- Manufacturer Fetch: *No direct TSS library equivalent.* Rely on `tpm2_getekcertificate` as an external process.

### Step 2: Verify EK Certificate Chain

Verify the EK certificate against known Manufacturer Root CAs.

**Pure Python:**
This remains a pure Python operation. Load root CAs and use **pyOpenSSL's `X509StoreContext`** to verify the chain. See the ASN.1 Compatibility section below for critical details.

### Step 3: Create EK + AK

Create an Endorsement Key (EK) and an Attestation Key (AK) bound to it.

**CLI (`tpm2-tools`):**
```bash
tpm2_createek -c ek.ctx -G rsa
tpm2_createak -C ek.ctx -c ak.ctx -G rsa -g sha256 -n ak.name
```

**Library (`tpm2-pytss`):**
Use `ESAPI.create_primary()` to create the EK in the endorsement hierarchy.
Use `ESAPI.create()` and `ESAPI.load()` to create and load the AK bound to the EK.

### Step 4: Credential Activation

Prove that the AK and EK live on the same physical TPM by encrypting a challenge to the EK and verifying the AK can decrypt it using a policy session.

**CLI (`tpm2-tools`):**
```bash
tpm2_makecredential -u ek_pub.tpm2 -s challenge.txt -n <ak_name_hex> -o cred.secret
tpm2_startauthsession --policy-session -S session.ctx
tpm2_policysecret -S session.ctx -c 0x4000000B
tpm2_activatecredential -c ak.ctx -C ek.ctx -i cred.secret -o decrypted.txt -P session:session.ctx
```

**Library (`tpm2-pytss`):**
- Creation: Use `tpm2_pytss.utils.make_credential()` (can be done offline).
- Session: Use `ESAPI.start_auth_session()` and `ESAPI.policy_secret()`.
- Activation: Use `ESAPI.activate_credential()`.

### Step 5: Key Certification (TPM2_Certify)

The AK signs a cryptographic proof that a specific workload key is inside the TPM.

**CLI (`tpm2-tools`):**
```bash
tpm2_createprimary -C o -g sha256 -G rsa -c owner_primary.ctx
tpm2_certify -c owner_primary.ctx -C ak.ctx -g sha256 -o attest.bin -s sig.bin
```

**Library (`tpm2-pytss`):**
- Setup: Use `ESAPI.create_primary()` in the owner hierarchy.
- Certification: Use `ESAPI.certify()` with the target key and the AK.

### Step 6: PKCS#11 Store Query

Find the relevant keys that a workload is using.

**CLI/Filesystem:**
Querying the raw `tpm2_pkcs11.sqlite3` database manually. *(Not recommended, fragile schema)*

**Library (`python-pkcs11`):**
Use the `python-pkcs11` library to interface with the PKCS#11 token directly and enumerate keys safely.

## 4. Key Concepts

- **EK (Endorsement Key)**: The manufacturer-provisioned, non-migratable primary key in the Endorsement hierarchy. It represents the physical hardware.
- **AK (Attestation Key)**: An ephemeral key created per-session, bound to the EK hierarchy. It is used to sign attestation data because the EK itself cannot be used for generic signing.
- **Credential Activation**: A cryptographic challenge-response protocol proving that an AK resides on the same TPM hardware as a specific EK.
- **TPM2_Certify**: A TPM command where an AK generates a signed structure (`TPM2B_ATTEST`) proving that another specified key currently resides in the TPM and has specific properties (like non-exportability).
- **Policy Sessions**: Advanced authorization sessions. Required because using the Endorsement hierarchy (for `activatecredential`) requires a `PolicySecret` authorization rather than simple password auth.

## 5. Python Libraries

### `tpm2-pytss` (pip)
Requires the `libtss2-dev` system package.
- **`ESAPI` class**: Direct 1-to-1 mapping to TPM2 commands (e.g., `create_primary()`, `create()`, `load()`, `certify()`, `activate_credential()`, `nv_read()`, `get_capability()`, `start_auth_session()`, `policy_secret()`).
- **`utils.make_credential()`**: A helper for offline credential creation without needing a TPM.
- **`tr_from_tpmpublic()`**: A crucial utility to map standard TPM handles into the ESAPI context (a major difference/gotcha compared to CLI tools).

### `python-pkcs11` (pip)
- Used for robust PKCS#11 token interaction (finding slots, tokens, and keys).
- Replaces raw SQLite queries against `tpm2_pkcs11.sqlite3`.

## 6. ASN.1 Compatibility (Critical)

A major recurring issue when verifying TPM certificates.

**Problem:** Real-world TPM EK certificates from vendors (e.g., Intel, Nuvoton) often have non-canonical DER encoding. The Python `cryptography` library's strict Rust-based X.509 parser rejects them with `InvalidSetOrdering` or unexpected `critical=FALSE` flags.
*(See: pyca/cryptography#7189)*

**Solution:** You MUST use `pyOpenSSL` (`OpenSSL.crypto`) for DER↔PEM conversion and certificate chain verification. It leverages the C OpenSSL library which is far more lenient with non-compliant ASN.1 structures.

## 7. Dead Ends

Avoid these architectural approaches:
- **Credential activation via subprocess**: Highly fragile. Requires managing temporary files, correctly formatting binary blobs, and specifically hex-encoding the AK name.
- **`tpm2_getekcertificate` pure library equivalent**: None exists in standard TSS. The tool performs HTTP fetches to manufacturer servers which the low-level TSS spec doesn't cover. Use the CLI tool via subprocess for this one step.
- **Direct SQLite queries**: Parsing `tpm2_pkcs11.sqlite3` directly breaks frequently because the database schema changes between tpm2-pkcs11 versions. Use `python-pkcs11` instead.

## 8. Key Differences from Windows

| Aspect | Linux | Windows |
|---|---|---|
| TPM interface | `/dev/tpmrm0` via `libtss2` / `tpm2-pytss` | `ncrypt.dll` PCP provider |
| Key attestation method | `tpm2_certify` (TPM2_Certify) | `NCryptGetProperty("PCP_TPM2BNAME")` |
| AK requirement | Yes — AK signs the certification | No — PCP stores creation data internally |
| Credential activation | Explicit `make_credential` / `activate_credential` | Not needed (PCP handles internally) |
| EK cert retrieval | `tpm2_getekcertificate` or NV read | PowerShell `Get-TpmEndorsementKeyInfo` |
| Admin required | Access to `/dev/tpmrm0` (usually `tss` group) | Usually non-admin works |

## 9. Error Reference

When using `tpm2-pytss`, errors surface as `TSS2_Exception`. You must check the return codes.

| Issue | TSS Return Code / Error | Fix |
|---|---|---|
| Permissions | `Could not open /dev/tpmrm0` | Add user to `tss` group or run as root. |
| Command not supported | `TPM2_RC_COMMAND_CODE` | Firmware is too old to support the command. |
| NV index empty | `TPM2_RC_NV_UNINITIALIZED` | The NVRAM index doesn't have a certificate. Fallback to `tpm2_getekcertificate`. |
| Bad session | `TPM2_RC_POLICY_FAIL` | Policy session expired or was set up incorrectly (e.g., missing policy_secret). |
